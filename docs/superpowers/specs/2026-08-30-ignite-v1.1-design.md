# Ignite v1.1 — Design

Date: 2026-08-30
Status: approved (verified against the live Codemagic API)

## Goal

Close the gap between what Ignite claims to do and what it actually does, and
cover the parts of the Codemagic API that a CI/CD admin app needs but the
current build never reached.

## Verified API surface

Every row below was checked with a real token against `https://api.codemagic.io`
on 2026-08-30. Rows marked *undocumented* do not appear in the Codemagic docs;
they were found by reading a community MCP client and then confirmed by hand.

| Endpoint | Result |
| --- | --- |
| `GET /apps` | 200. `applications[]` carries `lastBuildId`, `appEnvironmentVariables`, `workflows{}` (with `instanceType`), `iconUrl` (null on all three test apps) |
| `GET /apps/:id` | 200. Already used for workflow lookup |
| `GET /builds` | 200. Returns `{applications, builds}`. Params: `appId`, `limit`, `status`, `branch`, `workflowId`, `skip` all work; **`page` is ignored** |
| `GET /builds/:id` | 200. `{application, build}`; `build.buildActions[]` and `build.artefacts[]` are complete |
| `GET /builds/:id/step/:stepId` | 200, `text/plain`. Raw step log. *undocumented* |
| `POST /builds/:id/cancel` | 208 on an already-finished build, as documented |
| `DELETE /builds/:id` | **405 METHOD_NOT_ALLOWED** — what the app currently calls |
| `POST /artifacts/:path/public-url` | 200. Body `{"expiresAt": <unix>}`; artefact field `path` is the `secureFilename` |
| `GET /apps/:id/caches` | 200 `{"caches": []}`. *undocumented* |
| `GET /apps/:id/variables` | 200 `[]` — a **bare array**, not an object. *undocumented* |

Shapes worth pinning down:

- `buildActions[i]` = `{_id, name, status, startedAt, finishedAt, type, results, subactions[]}`.
  `status` is one of `success` / `failed` / `skipped` / `canceled`.
  Each `subactions[i]` has `command` and a `logUrl` pointing at
  `/builds/:buildId/step/:actionId` — the parent action's `_id`.
- `artefacts[i]` = `{name, type, url, size, version, versionName, versionCode, supportedPlatforms, path}`.
- Builds age out of `GET /builds` (retention), but `GET /builds/:id` still serves
  them. An empty Builds tab does not mean the app never built.

## Decisions this forced

1. **Cancel is broken, not missing.** `DELETE /builds/:id` returns 405, so the
   Cancel Build button has never worked. Fix the verb and path; treat 208 as
   success rather than an error.
2. **`page` must become `skip`.** Passing `page` silently returns the full list,
   so any pagination built on it would quietly show duplicates.
3. **Variables need their own decoder.** `_get()` casts the body to
   `Map<String, dynamic>`; the variables endpoint returns a top-level array and
   would throw. Add a list-returning helper rather than widening `_get()`.
4. **`fileWorkflowIds` is empty** even on `settingsSource: file` apps, so the
   existing GitHub-raw fetch of `codemagic.yaml` stays. No change there.
5. **`iconUrl` is null everywhere**, so app cards keep the generated icon.
6. **Artifact download stays native-only.** `dart:io` compiles for web (the
   release build passes) but `getTemporaryDirectory()` throws at runtime. On web,
   use the public-url endpoint and hand the browser a link instead.

## Architecture

The existing layering holds — models, an HTTP service, Riverpod providers, and
pages — so this is additive. No restructuring.

### Service — `lib/core/services/codemagic_api.dart`

Add a `_getText()` for `text/plain` responses and a `_getList()` for endpoints
that return a bare array. Then:

```
cancelBuild        POST   /builds/:id/cancel          (208 => success)
getBuildDetail     GET    /builds/:id                 -> CmBuild + buildActions
getStepLog         GET    /builds/:id/step/:stepId    -> String
artifactPublicUrl  POST   /artifacts/:path/public-url -> String
getCaches          GET    /apps/:id/caches
deleteCache        DELETE /apps/:id/caches/:cacheId
deleteAllCaches    DELETE /apps/:id/caches
getVariables       GET    /apps/:id/variables         (bare array)
addVariable        POST   /apps/:id/variables
updateVariable     PUT    /apps/:id/variables/:varId
deleteVariable     DELETE /apps/:id/variables/:varId
triggerBuild       + tag, + instanceType
getBuilds          page -> skip
```

### Models — `lib/core/models/app_model.dart`

`CmBuildAction`, `CmCache`, `CmVariable` are new. `CmApplication` gains
`lastBuildId`; `CmArtifact` gains `path` (the secure filename) and `versionName`.
`CmBuild` gains `buildActions`, `instanceType`, and `tag`.

### Providers — `lib/core/providers/codemagic_provider.dart`

`buildDetailProvider`, `stepLogProvider`, `cachesProvider`, `variablesProvider`,
plus `latestBuildsProvider` — one unfiltered `GET /builds` reduced to a
`Map<appId, CmBuild>` for the home cards, rather than one request per app.
Search adds `appSearchQueryProvider` and a derived `filteredAppsProvider`.

### UI

| Surface | Change |
| --- | --- |
| `apps_page` | Search field; last-build status chip on each card; account switcher sheet (switch / rename / remove / add) |
| `app_detail_page` | Fill the empty `actions: []` with an overflow menu into Caches and Variables |
| `build_detail_sheet` | Steps section from `buildActions`; artifact share-link action; platform-split download |
| `step_log_page` *(new)* | Monospace `SelectableText`, copy-all |
| `caches_page` *(new)* | Cache list with size and last-used, delete one or all behind a confirm |
| `variables_page` *(new)* | Grouped CRUD, `secure` values masked |
| `yaml_trigger_page` | Branch/tag toggle, instance-type dropdown |
| all | Shimmer skeletons in place of spinners |

Adding a second account has to reach the login form, which the router currently
redirects away from whenever a token exists. `/login` gains an `add=true` query
parameter and the redirect learns to let that through.

## Error handling

Unchanged in shape: `CodemagicApiException` from the service, caught at the UI
edge, surfaced as a SnackBar. Two additions — 208 from cancel is a success, not
an error, and cache and variable mutations invalidate their provider on return
so the list reflects the server rather than an optimistic guess.

## Testing

Unit tests for pure logic only, no widget tests: the search filter, the
`AccountsNotifier` add/switch/rename/remove cycle, and JSON parsing for
`CmBuildAction`, `CmCache`, `CmVariable`, and `CmArtifact.path`. Everything that
touches the network is verified by running the app against the real account.

## Out of scope

Creating and deleting applications (`POST /apps`, `POST /apps/new`,
`DELETE /apps/:id`), webhook management, and build scheduling. All exist in the
API; none of them are what this app is for yet.
